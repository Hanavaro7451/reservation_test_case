# Reservation API

REST API для бронирования столиков на FastAPI, SQLAlchemy и SQLite.

## Запуск

Нужен `uv` и Python 3.14 или новее. Выполни команды из корня проекта.

Скопируй `.env.example` в `.env`. Для PowerShell:

```powershell
Copy-Item .env.example .env
```

Для Bash:

```bash
cp .env.example .env
```

Установи зависимости, примени миграции и запусти приложение.

```bash
uv sync --locked
uv run --locked alembic upgrade head
uv run --locked uvicorn main:app
```

API можно проверить в [Swagger UI](http://127.0.0.1:8000/docs).

## Эндпоинты

| Метод и путь | Поведение |
| --- | --- |
| `POST /bookings` | Создаёт активную бронь и возвращает её с `201`. Занятый слот даёт `409`. |
| `GET /bookings` | Возвращает список броней, включая отменённые. Для фильтрации передай `?date=YYYY-MM-DD`. |
| `GET /bookings/{id}` | Возвращает бронь по идентификатору или `404`. |
| `DELETE /bookings/{id}` | Возвращает `200` и бронь со статусом `cancelled`. Повторная отмена возвращает тот же результат. |

При создании передай `name`, `phone` в формате `+7XXXXXXXXXX`, `booking_date` в формате `YYYY-MM-DD`, `booking_time` в формате `HH:MM` и `guests` от 1 до 10. Брони принимаются на целые часы с `12:00` по `22:00` по московскому времени, на сегодня и до 30 дней вперёд включительно.

## Решения

Роуты отвечают за HTTP, сервис — за правила бронирования, репозиторий — за запросы к БД. SQLite хранит брони между перезапусками, а Alembic воспроизводит схему на чистой базе. Частичный уникальный индекс защищает активный слот при параллельных запросах и освобождает его при отмене. Отмена меняет статус записи, поэтому история остаётся доступной в списке и по идентификатору.

## Тесты

```bash
uv run --locked python -m pytest
```

Каждый тест использует отдельную временную SQLite с миграциями Alembic. Тесты проверяют конфликт при параллельной брони, повторную бронь после отмены и чтение с фильтром по дате.
